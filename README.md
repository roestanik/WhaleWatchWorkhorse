# WhaleWatchWorkhorse

## Workhorse
Noun, a person who does a lot of work, especially of a type that is necessary but not interesting. (Cambridge Advanced Learner's Dictionary & Thesaurus)

## What is the WhaleWatchWorkhorse?
The WhaleWatchWorkhorse is a collection of PYTHON (driver-) scripts and functions as well as some data.
The goal of this collection is to produce a noise impact assessment for seismic surveys as required by Danish and German authorities.
Also there is the functionality to produce the data report for the MarineEars noise registry for the German BSH and tables of noise emission in ICES subrectangles.

### How does it work?
There are driver scripts for both for the noise impact assessment and the data report.
Parameters are stored in YAML-files.
An example for a noise impact assessment for a seismic source, a single beam and a multi beam echo sounder is given in Pre_NoiseAssessment/ImpactAssessment_Seismics.py.
In this driver script reference is made to the parameter YAML-files. The driver script calls Pre_NoiseAssessment/ImpactAssessment_SeismicsReport.py to generate the reports.
The basic functions are given in Pre_NoiseAssessment/ImpactAssessment_Functions.py.

The data report is a hdf5 file as specified in the pdf-Document Post_Reporting/2021_09_24_data_requirements_for_seismic_surveys.pdf.
The report is generated by executing Post_Reporting/MarineEarsReporting.py, which calls Post_Reporting/MarineEarsReportingFuncs.py with all  functions necessary.
A hdf5 file and txt-files containing a track with 15min increments, positions and ICES subrectangle information as well as sound source infos is produced.

Data necessary to produce the assessment and the report are given in the data folder.
This directory includes:
- ExampleProfiles with segy-files of a data example for every sound source,
- FilterFunctions with the limits for sound exposure, the parameters for the audiograms and weight functions from Southall et al. 2019.
- A navigation folder such as NAV-Heincke-Bridge (name to be specified in the YAML of the data report).
- Protocol with profile lists, whose format has to be followed.
- Sources with measurements and specifications for the sound sources used.
- Spreading models to include e.g. KRAKEN models for geometric spreading.
The names inside the data folders need to match to the YAML files for the assessment and the report.

### Who will use this project?
Most likely academic working groups will use those scripts to produce noise impact assessments for their surveys.

## Instructions

### Usage: How do I get this project to work on my machine?
Make sure to have a working PYTHON installation, an installation of ANACONDA with SPYDER might be the easiest option. 
Ensure that the following packages are running and install if necessary (alphabetic order, see LICENSE-file for more info):
- copy
- datetime
- matplotlib
- numpy
- os
- pandas
- pathlib
- pynmea2
- pylatex
- scipy
- segysak
- yaml

Open Pre_NoiseAssessment/ImpactAssessment_SeismicsReport.py or Post_Reporting/MarineEarsReporting.py set the working directory to the file and execute.
There are progress messages and error messages.

### Development: How can I develop for this project?
#### Test
Up to now 2022.07.12 no tests have been written. This step might be most important. Quality control so far consits of comparisons to publised studies,

### Data
The use of new source types requires the addition of more measurements and specifications.
Also the sound exposure limits need to be updated and extended for all animal hearing groups.

### Spreading models
It would be great to directly include a normal mode spreading model into the noise assessment, as this model has a great influence on all calculations.
